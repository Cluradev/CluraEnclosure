# Clura Enclosure - Firmware Guide

Welcome to the Clura Enclosure firmware! This guide covers everything you need to flash firmware and customize your enclosure's behavior.

---

## Quick Start

Files contained in this folder:
1. Bootloader_v1Soft - bootloader for the board, allows to easily update the firmware. All boards come pre flashed with this
2. Monitor - main firmware of the application to be flashed with an st link on the board, so if one wishes to not have the bootloader (mainly for testing)
3. MonitorBTL - main firmware of the board, flashed using monitor.bin file
4. Screen UI - contains HMI editable file, and monitorHMI.tft (to be renamed firmware.tft in order to flash the screen)
5. SD Card files - monitor.bin (file to flash the latest firmware), filament.clu (file to edit the filaments on the EEPROM, it's automatically generated by the board), data.clu (allows many parameters of the board to be adjusted, needs to be copied onto the sd card)

### Flashing Firmware

The easiest way to update your Clura Enclosure is using an SD card.

#### Main PCB Update

1. Copy your build to the root of the SD card and **name it exactly `monitor.bin`**
2. Insert the SD card into the main PCB
3. Power on the enclosure
4. Wait for the confirmation message on screen
5. The system will automatically reboot with new firmware

> **The filename matters.** The bootloader only ever looks for `monitor.bin`

The bootloader **checks the image before erasing anything**: it verifies the file
size, reads it end to end, and confirms it looks like real firmware. Only then does it
erase and program, and afterwards it verifies what was written. If any of that fails it
shows the failure page and leaves your existing firmware untouched. `monitor.bin` is deleted only after a
successful, verified update.

#### Screen Update

1. Copy `firmware.tft` to the root of your SD card (this is `monitorHMI.tft` renamed)
2. Insert the SD card into the screen
3. Power on the screen
4. Wait for flashing to complete
5. **Remove the SD card** and power cycle the screen

> **Note**: Never remove power during flashing!

## Customizing Your Enclosure

### The data.clu File

`data.clu` holds the enclosure's **tuning parameters** - thresholds, angles, timings.
It lets you retune a machine without rebuilding the firmware.

**Location**: Root of SD card
**Format**: Plain text, `key = value`, one per line. `#` starts a comment.

> **This file is read-only from the enclosure's point of view.** It is never written or
> updated by the machine. Your day-to-day settings (brightness, fan speeds, filament
> choice, calibration) live in the enclosure's internal memory and are **not** in this
> file. That separation is deliberate: it means the card can stay in the machine
> permanently without ever overwriting what you set on the touchscreen.

#### How it is applied: `configRevision`

Every `data.clu` starts with a revision number:

```ini
configRevision = 8
```

The enclosure remembers the last revision it applied, and only reads the file when the
number in it is **higher**. So:

* Leave the card in permanently - on a normal boot the file is ignored entirely.
* To push a change: **edit the value, raise `configRevision`, power-cycle.**
* The same card configures every machine you insert it into, once each.
* To undo a change, restore the old value **and raise the number again.** Never reuse a
  number.

A file with no `configRevision` line is ignored completely.

> **After a firmware update, leave `data.clu` on the card for the first boot.** A
> firmware update can reset the tuning block to its defaults, and the file will
> immediately re-apply itself.

#### Safety

Every value is clamped to the range shown next to it. A typo cannot disable thermal
protection or drive the servo into a mechanical stop. Keys you leave out keep their
current value; unknown keys are ignored.

#### What you can tune

**Servo / flap**

| Key | Range | Meaning |
|---|---|---|
| `servoOpenAngle` | 1-90 | Flap open position (also used for the overtemp vent) |
| `servoCloseAngle` | 1-90 | Flap closed position |
| `servoHoldMs` | 100-3000 | How long the servo is driven before it powers down |
| `servoTempHyst` | 1-10 | Hysteresis on the overtemp vent, in °C |

**Safety**

| Key | Range | Meaning |
|---|---|---|
| `maxTemp` | 35-80 | Temperature that forces the flap open, in °C |
| `opticalAlarmEnable` | 0-1 | `0` = the optical smoke sensor is ignored |
| `smokeFireResponse` | 0-1 | `1` = on smoke, all fans stop and the flap closes |
| `lpgThreshold` | 100-4095 | MQ2 gas trigger level |
| `smokeThreshold` | 100-4095 | MEMS smoke trigger level |
| `smokeBeginTime` | 0-900000 | Warm-up before the alarm arms, in ms |

**Fans**

| Key | Range | Meaning |
|---|---|---|
| `autoCoolTempMin` / `autoCoolTempMax` | 0-60 | Cooling fan ramp, in °C |
| `autoFilterImpMin` / `autoFilterImpMax` | 0-1000 | Filter fan ramp on PM2.5 |
| `autoFilterP03Min` / `autoFilterP03Max` | 0-10000 | Filter fan ramp on PM0.3 |
| `extraFanSpeed` | 0-100 | Fixed speed of the extra fan when switched on, in % |

**Intervals and display**

| Key | Range | Meaning |
|---|---|---|
| `bmeSampleInterval` | 1000-60000 | Time between temperature/VOC readings, in ms |
| `usageLogInterval` | 60000-3600000 | How often the usage counter is saved, in ms |
| `sensorUsageWarnHours` | 0-20000 | Runtime **hours** before the "replace sensor" icon |
| `minBrightness` | 5-100 | Lowest screen brightness the UI will allow |
| `countdownTime` | 1-60 | Calibration "continue" countdown, in seconds |

**Load-cell factory seeds**

`defaultLeftCal`, `defaultRightCal`, `defaultLeftOffset`, `defaultRightOffset`,
`tareWeight`.

These are only used by a machine that has **never** completed calibration. Once a unit
is calibrated it keeps its own measured values forever, and changing these will not
disturb it. They are also what the "restore defaults" button writes back.

## How Key Features Work

### The Flap

The flap is controlled by the **OPEN/CLOSE button on the fan page**. 

Each press drives the servo to the new position and then **powers it down** after
`servoHoldMs`. This is intentional: it stops the servo buzzing and drawing current
while holding position.

Two safety rules override the button, in this order:

1. **Smoke detected** → the flap **closes**
2. **Temperature above `maxTemp`** → the flap **opens**

Smoke deliberately outranks temperature. A fire raises the temperature too, so without
that ordering the enclosure would vent the fire while trying to starve it.

### Automatic Cooling

When auto cooling is enabled, the cooling fan follows the temperature:

- **At or below `autoCoolTempMin` (20 °C)**: fan off
- **Between the two**: fan speed increases linearly
- **At or above `autoCoolTempMax` (40 °C)**: fan at 100%

### Automatic Filtering

When auto filtering is enabled, the filter fan follows air quality:

- Monitors **PM2.5** and **PM0.3** particle counts
- Uses whichever indicates worse air
- Below both thresholds the fan is **off**, not idling
- Once either threshold is crossed it starts at **20%** and ramps to 100% with
  concentration, so there is a step from 0% to 20% at the threshold

PM1 and PM10 are measured and written to the log, but they do not affect fan speed.

### Overtemperature

If the temperature passes `maxTemp` **and there is no smoke**:

- The flap **opens** and is held open
- **Every fan runs at 100%** to pull the heat out

It returns to normal once the temperature drops below `maxTemp - servoTempHyst`. This
needs the BME sensor enabled - with no temperature source there is nothing to act on.

### Fire Alarm

Two sensors can raise the alarm by default:

1. **MQ2 gas sensor** - LPG, propane, smoke
2. **MEMS sensor** - smoke

A third, the **optical smoke sensor, is disabled by default** (`opticalAlarmEnable = 0`).
Its input is pulled high and reads "smoke" when nothing is connected, so an absent or
faulty sensor would hold the alarm on permanently. Enable it only once a working sensor
is fitted, and check that it reads clear when idle.

The alarm has a warm-up period after power-on (`smokeBeginTime`) to avoid false trips
while the gas sensors heat up.

When triggered:

- **Buzzer sounds** (unless muted)
- **LED strip turns red** (if the alarm indicator is enabled)
- **Every fan stops** and **the flap closes** - so the enclosure is not feeding oxygen
  to a fire or pushing smoke out through the filter

Muting only silences the buzzer. It does **not** restart the fans or reopen the flap.

## Spool Holder System

The dual spool holders track filament weight in real time using load cells.

### How It Works

1. **Calibrate the load cells** (one-time setup via touchscreen)
2. **Select your filament brand** from the list, or add a custom one
3. The system shows: `Remaining Filament = Current Weight - Empty Spool Weight`

With an empty holder the display shows the **negative spool weight** - for example
`-202` when a 202 g spool is selected. That is normal, and tells you at a glance both
that the holder is empty and which spool is configured.

`-404` means the load cell is not responding or is disabled, not a weight.

### Filament Profiles

The enclosure ships with 16 preset filament brands and has room for **24 in total**, so
you can add 8 of your own. Each entry stores a brand name and an empty spool weight in
grams. The library lives in the enclosure's memory and is mirrored to `filament.clu`
on the SD card.

### Adding Custom Filament

Via the touchscreen calibration menu:

1. **Tare**: remove the spool and zero the scale
2. **Weigh**: place a **full** spool to measure the total weight
3. **Name**: enter the brand name
4. **Save**: the profile is stored and `filament.clu` is updated

> The empty-spool weight is worked out as *measured weight − `tareWeight`*, where
> `tareWeight` (default 1000 g) is the assumed weight of the filament itself. **Use a
> full, unused spool** - a partly used one gives a wrong result.

### The filament.clu File

Unlike `data.clu`, this file works **both ways**:

- If it is missing, the enclosure **creates it** from its current library
- Whenever you register a spool on the machine, the file is **rewritten** to match
- If you edit the file and raise `filamentRevision`, the enclosure **imports** it

```ini
filamentRevision = 3
filamentCount    = 17

filament0  = Sunlu,134
filament1  = Prusament,198
filament16 = My Custom PLA,205
```

To add a spool by hand: add a `filament<n>` line and **raise `filamentRevision`**. The
number of entries is worked out from the highest `n` present, so you do not have to
touch `filamentCount`.

> `filamentRevision` must be **higher** than the number the machine last applied, or the
> file is ignored. In practice the number in the file is the applied one, because both an
> import and an export leave the two in step, so read it and go above it. Note the file is
> only rewritten when it is missing at boot or when you register a spool on the
> touchscreen - it is not refreshed on every ordinary boot.

> One card shared between machines with different custom spools will end up holding
> whichever machine wrote last. Raise the revision to make one library authoritative.

## Advanced Configuration

### Compile-Time Settings (parameters.h)

Most tuning is now done through `data.clu` and needs no rebuild. The values in
`Core/Inc/parameters.h` are the **defaults** used when a machine has no tuning stored -
`data.clu` overrides them.

You only need to rebuild for things that are not tunable, such as screen page IDs,
image IDs, or the number of filament slots.

To change a default: edit `parameters.h`, rebuild in STM32CubeIDE, and reflash.

## Data Logging

Enable logging via the touchscreen to track environmental data over time.

**Log File**: `log.csv` on SD card

**Columns**:

```
BootID, MinSinceBoot, Temperature, Humidity, Pressure, Smoke,
PM 0.3, PM 2.5, PM 10, VOC, LPG, Fan Speed, Left Weight, Right Weight
```

`BootID` counts power-on sessions and `MinSinceBoot` is minutes since that power-on.
The enclosure has no real-time clock, so sorting by **BootID then MinSinceBoot** gives
you correct chronological order across reboots.

Two columns are easy to misread:

* **`Pressure` is in Pascals**, straight from the BME680, so a normal sea-level reading is
  about 101325 rather than 1013. Divide by 100 for hPa or mbar.
* **`VOC` is not a gas resistance.** It is an air-quality score computed from the BME680's
  gas reading and the humidity, on a 0-500 scale where **lower is better**. It is scored
  against a rolling internal reference, so it is meaningful over time on one machine rather
  than as an absolute figure to compare between machines.

**Intervals**: 5, 10, or 60 minutes.

The file is only appended to, so it can grow indefinitely - roughly 18 KB per day at the
5-minute interval.

## Machine Usage Counter

The enclosure counts hours of **filter-fan runtime** and shows a "replace sensor" icon
once it passes `sensorUsageWarnHours` (default 600 h). Both automatic and manual
filtering count toward it. It can be reset from the settings page.

## Troubleshooting

**SD Card Not Recognized**
- Format as FAT32 (exFAT is not supported)
- Insert before powering on
- Check for physical damage

**Firmware Update Does Nothing**
- The file must be named exactly `monitor.bin`
- Check you copied the newest build - confirm its timestamp

**Firmware Update Shows the Failure Page**
- The image was rejected before anything was erased; your firmware is intact
- Usually a corrupted or incomplete copy - copy `monitor.bin` again

**Sensors Not Working**
- Verify connections
- Enable the sensor in the Features menu
- Check the System Check page for sensor status

**Load Cells Inaccurate**
- Recalibrate via the touchscreen
- Tare with an empty holder
- Check for mechanical interference

**Spool Shows -404**
- The load cell is not responding, or load cells are disabled in Features

**Added a Spool to filament.clu but Cannot Select It**
- Raise `filamentRevision` - without that the file is not read at all

**Changed data.clu but Nothing Happened**
- Raise `configRevision`. The file is only read when the number increases

**False Fire Alarms**
- Wait out the warm-up period after power-on (`smokeBeginTime`)
- Check the readings on the Sensors page
- If the optical sensor was enabled, confirm it reads clear when idle - an unconnected
  sensor reads as permanent smoke
- Adjust `lpgThreshold` / `smokeThreshold` in `data.clu`

**Fans Will Not Run**
- Check whether the alarm is active - smoke stops every fan by design
